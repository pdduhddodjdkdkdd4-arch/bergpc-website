# 修复计划：律师管理功能和表单提交问题

## 问题概述

用户报告了以下问题需要修复：

1. 新增律师后显示 "Invalid request. Please try again." 错误
2. 点击编辑律师跳转到 404 页面，而不是弹出编辑模态框
3. `/api/submit.php` 返回 "No form data provided" 错误
4. 数据库 `form_submissions` 表只存储基本数据，未满足需求，需要：

   * 统一所有 "Tell Us About Your Case" 表单与 fraud-recovery 页面一致

   * 检查所有用户填写的表单，收集统计表单项，后台管理需要展示完整的表单字段

   * 考虑其他按钮的表单差异（Contact a Crypto & Blockchain Lawyer、Get Started 等）

## 一、问题分析

### 1.1 新增律师错误

**根因分析**：CSRF token 验证失败

从代码来看：

* `admin/lawyers.php:9-12` 有 CSRF 验证

* `admin/session.php:112-120` 验证 CSRF token

* 可能原因是会话问题或 token 不匹配

### 1.2 编辑律师 404 问题

**根因分析**：当前代码使用 `<a href="lawyers.php?edit=1">` 跳转，但页面实际支持 `?edit=ID` 参数

* `admin/lawyers.php:200-208` 已经有处理编辑的逻辑

* 但编辑按钮仍然使用链接跳转，而不是 JavaScript 打开模态框

* 需要修改为不跳转，直接通过 JS 显示模态框并加载数据

### 1.3 表单提交 "No form data provided"

**根因分析**：PHP 会自动将 `wpforms[fields][13][first]` 这样的表单名解析为嵌套数组，
而当前 `api/submit.php:38-43` 直接查找 `$_POST` 中键名以 `wpforms[fields]` 开头的，
但实际上 PHP 解析后键名是 `wpforms`，值是嵌套数组，所以找不到。

### 1.4 表单字段统一和数据库扩展

**需求**：

* 所有 "Tell Us About Your Case" 表单与 fraud-recovery 页面一致

* 检查所有用户填写的表单，收集统计表单项，数据库需要能够存储所有字段

* 后台要展示完整字段

从 fraud-recovery 页面可以看到部分表单项有：

* 27: General Contact Disclaimer (checkbox)

* 13: Name (first/last)

* 1: Email

* 25: Phone

* 26: Address (address1/city/state/country)

* 17: Company

* 2: Case Details

* 4: (可能是某个字段)

* 18: Cryptocurrency Type

* 19: Amount Lost

* 3: (honeypot)

* 30: How Did You Hear About Us?

* 20: Date of Loss

* 21: Transaction ID

* 22: Additional Information

* 9: Disclaimer

## 二、修复方案

### 2.1 修复新增律师 CSRF 问题

1. 检查 CSRF token 生成和验证流程
2. 确保会话正确启动
3. 可能需要简化或调试 CSRF 验证（或者临时移除以便测试）

### 2.2 修复编辑律师 404 问题

1. 修改编辑按钮，从链接改为按钮
2. 使用 JavaScript 打开模态框，而不是跳转页面
3. 确保编辑数据能正确加载到表单中

### 2.3 修复表单提交问题

1. 重构 `api/submit.php` 中的数据收集逻辑
2. 正确处理 PHP 解析后的嵌套数组结构
3. 添加递归函数来扁平化数组
4. 确保所有表单数据都被正确提取和存储

### 2.4 统一表单和扩展数据库

1. 创建数据库迁移脚本，扩展 `form_submissions` 表的字段以及收集到用户填写的字段（非管理员）
2. 修改后台管理页面 `admin/forms.php`，确保展示所有字段

## 三、实施步骤

### 步骤 1：修复律师管理页面 (admin/lawyers.php)

* 修改编辑按钮，添加 JavaScript 处理

* 确保 CSRF token 能正常工作（可能需要调试）

* 优化模态框显示逻辑

### 步骤 2：修复表单提交 (api/submit.php)

* 重写数据提取逻辑，处理嵌套数组

* 添加辅助函数来递归解析表单数据

* 确保所有字段都被正确保存

### 步骤 3：修改后台表单管理 (admin/forms.php)

* 优化字段显示逻辑

* 确保能正确显示所有表单数据

* 改进详情查看功能

### 步骤 4：创建测试和验证

* 测试新增律师功能

* 测试编辑律师功能

* 测试表单提交功能

* 检查后台展示

## 四、风险和注意事项

1. 修改 CSRF 验证时要注意安全性
2. 修改数据库结构前要备份
3. 确保兼容性，不影响现有功能
4. 测试不同浏览器和环境
